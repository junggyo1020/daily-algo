# 하루 한 문제 루틴

목표는 "많이 푸는 것"이 아니라 **실력이 녹슬지 않게 유지하고, 녹슨 지점을 매주 정확히 아는 것**이다.
그래서 이 루틴은 새 문제 풀이보다 **간격 반복 복습**과 **오답 원인 분류**에 비중을 둔다.

전제: 퇴근 후 45분. 작업 디렉토리는 이 저장소 루트(`~/willy/GitHub/daily-algo`)다.

## 시작하기 전에 지켜야 할 것

**코드를 먼저 쓰지 않는다.** 사용자가 스스로 떠올리고 작성하는 것이 이 루틴의 전부다.
막혔다고 해서 코드를 보여주면 그날 학습은 0이 된다. 막힘은 7단계의 절차로 처리한다.

**유형을 함부로 말하지 않는다.** `실전` 단계에서는 유형을 알려주는 것 자체가 정답 공개다
(`유형미인지`가 코딩테스트 최대 실점 원인이다). 단계별 공개 범위는 3단계에서 확인한다.

## 1단계 — 오늘 할 일 결정 (30초)

```bash
cd ~/willy/GitHub/daily-algo && python3 scripts/algo.py today
```

이 출력이 그날의 계획이다. 임의로 바꾸지 않는다. 엔진은 "밀린 복습 2일 이상 → 복습 우선,
진단 단계 → 미터치 유형 순서대로, 그 외 → 최저 숙련도 유형" 규칙으로 정한다.
사용자가 다른 걸 하고 싶다고 하면 따르되, 복습이 밀려 있다는 사실은 한 문장으로 알린다.

`_workspace/02_curriculum.md`가 있으면 그 주 계획의 해당 날짜 항목을 우선한다(주간 사이클이
이미 문제까지 확보해둔 경우다).

## 2단계 — 컨디션 확인 후 모드 선택

첫 질문은 하나만 한다: **"오늘 45분 가능? 아니면 축소모드(25분)?"**

| 모드 | 구성 | 쓸 때 |
|---|---|---|
| 기본 45분 | 개념 8분 → 풀이 25분 → 피드백 7분 → 기록 5분 | 평소 |
| 축소 25분 | 개념 생략 → 복습 또는 Lv.1 신규 20분 → 기록 5분 | 야근·피로·교대 |
| 타임어택 60분 | 2문제 블라인드, 개념·피드백은 끝에 몰아서 | 주말 선택 |

축소모드도 **기록은 반드시 남긴다**. 기록이 빠지면 숙련도 감쇠가 잘못 계산돼 대시보드가 거짓이 된다.

## 3단계 — 개념 리마인드 (8분, 신규일 때만)

`algo-concept` 스킬을 호출해 그날 유형의 개념을 설명한다. 단계별 규칙:

| 단계 | 개념 설명 | 유형 공개 |
|---|---|---|
| 진단 | 전체 설명 | 공개 |
| 보강 | 약한 개념만 집중 | 공개 |
| 실전 | **생략** | **비공개 — "오늘은 유형 비공개입니다"라고만 말한다** |

복습일에는 개념 설명 대신 **지난 오답 원인 한 줄만** 상기시킨다
(예: "지난번엔 방문처리 시점 때문에 틀렸다"). 풀이 방법은 다시 말하지 않는다.

`algo.py today`가 출력하는 **이전 풀이 경로(`solution_path`)를 지금 열지 않는다.** 읽어서
"아 맞다"가 되는 건 복습이 아니다. 그 파일은 7단계 피드백에서 새 풀이와 비교할 때만 연다.

## 4단계 — 문제 제시와 작업 파일 생성

문제는 `algo.py today`가 지정한 것, 주간 계획에 있는 것, 없으면 `algo-problem-scout` 에이전트를
`model: "opus"`로 호출해 확보한다. **문제 번호를 기억으로 쓰지 않는다** — 실재 확인 없이 쓴 링크는
반드시 깨진다.

`.claude/skills/algo-daily/assets/Solution_template.java`를 복사해 작업 파일을 만든다:
```
src/main/java/daily/D{YYYYMMDD}_{문제id}_{짧은제목}.java
```
플레이스홀더(`{{CLASS}}`, `{{PARAMS}}` 등)를 채우고, 예제 입출력은 `check(...)` 호출로 넣는다.
`solution` 본문은 **비워둔 채로 넘긴다.**

그리고 타이머를 알린다: "목표 N분. N분에 못 풀면 거기서 멈춘다." 이 벽이 중요한 이유 —
한 문제에 1시간 쓰면 다음 날 루틴이 깨진다. 코딩테스트도 시간제한 경기다.

## 5단계 — 사용자가 푸는 동안

말을 걸지 않는다. 사용자가 질문하면 6단계 규칙으로만 답한다.
완성했다고 하면 바로 실행해 자가검증부터 시킨다:
```bash
cd ~/willy/GitHub/daily-algo && java src/main/java/daily/D...java
```
`ALL PASS`가 아니면 아직 피드백 단계가 아니다. 그리고 **제출 전 반례 2개**를 스스로 채웠는지 확인한다
(빈 입력/원소 1개/최댓값/동일값). 예제만 통과하고 제출해서 틀리는 것이 가장 흔한 실점이다.

## 6단계 — 막혔을 때 (3단 사다리)

순서를 건너뛰지 않는다. 한 단 올릴 때마다 기록되는 `outcome`이 나빠지므로, 사다리 자체가 측정 장치다.

1. **10분 막힘** → 질문만 돌려준다: "입력 크기가 얼마고, 그걸로 허용되는 복잡도는?"
   "이 문제를 완전탐색으로 풀면 몇 번 연산인가?" 답을 주지 않는다.
2. **18분 막힘** → 유형만 공개한다(실전 단계라면 이때 해제). `outcome`은 최소 `solved_with_hint`가 된다.
3. **25분(목표시간) 초과** → **중단한다.** 코드도 풀이도 보지 않는다.
   `outcome: failed`로 기록하고 내일 1순위 복습으로 자동 올라간다.
   이게 패배가 아니라 설계다 — 못 푼 문제를 다음날 다시 만나는 게 가장 효율적인 학습이다.

## 7단계 — 피드백 (7분)

`algo-feedback` 스킬로 진행한다. 정답이어도 생략하지 않는다 — 시간복잡도와 Java API 선택이
실전 점수를 가른다.

## 8단계 — 기록 (5분, 생략 불가)

먼저 노트를 쓴다 — `notes/{YYYY-MM-DD}.md`:
```markdown
# 2026-11-09 · 스택·큐·덱 · 기능개발 (Lv.2)
## 어떻게 접근했나
## 막힌 지점과 이유
## 배운 Java API / 패턴
## 다음에 같은 실수를 막을 체크 한 줄
```

그리고 로그에 적재한다:
```bash
python3 scripts/algo.py log \
  --platform programmers --id 42586 --title "기능개발" --level 2 \
  --types t04 --minutes 23 --outcome solved_over_time \
  --attempts 2 --errors 경계조건 --mode new \
  --path src/main/java/daily/D20261109_42586_기능개발.java \
  --url "https://..." --note "덱 회전에서 인덱스 꼬임"
```

`--target`을 생략하면 유형×난이도 기본 목표시간이 자동으로 들어간다. 실제로 다른 목표를 걸고
풀었을 때만 명시한다. `--date`도 생략하면 오늘이다 — **형식이 틀리면 기록을 거부**하므로
날짜를 손으로 쓸 일이 있으면 `YYYY-MM-DD`를 지킨다.

`outcome` 판정 기준 — 느슨하게 주지 않는다. 숙련도 점수 전체가 여기서 나온다.

| outcome | 조건 |
|---|---|
| `solved_in_time` | 힌트 없이, 목표시간 내, 첫 제출 정답 |
| `solved_over_time` | 힌트 없이 풀었지만 목표시간 초과 또는 재제출 |
| `solved_with_hint` | 6단계 사다리 2단 이상을 썼다 |
| `failed` | 25분 벽에서 중단 |

**최종 정답이어도 과정에서 틀린 게 있으면 `--errors`에 반드시 분류한다.** 정답 여부보다
과정의 실수가 실제 약점이다. 원인 8종은 `data/types.json`의 `error_causes`에 있고,
`solved_in_time`이 아니면 엔진이 `--errors`를 강제한다.

마지막으로 대시보드와 커밋:
```bash
python3 scripts/algo.py export
git add -A && git commit -q -m "$(date +%Y-%m-%d) 기능개발 (스택·큐·덱, solved_over_time)"
git push
python3 scripts/algo.py stats
```
커밋 그래프 자체가 학습 로그다. 그래서 하루 1커밋을 지킨다.

**커밋은 사용자 본인 명의다.** 저장소 로컬 git 신원이 이미 설정돼 있으니 `-c user.email=...`로
덮어쓰지 않는다. 그리고 커밋 메시지에 `Co-Authored-By: Claude`나 생성 도구 표기를
**붙이지 않는다** — 이 저장소는 사용자의 공개 학습 기록이고, 커밋은 사용자가 푼 문제의 기록이다.

## 마무리 한마디

`stats` 출력에서 **오늘 바뀐 지표 한 개만** 짚는다(예: "스택·큐·덱 0 → 70, 이제 미진단 7개 남음").
전체 표를 다시 해설하지 않는다. 지친 상태에서 긴 요약은 읽히지 않는다.
주간 진단이 밀렸으면(`this_week`가 5에 도달했거나 토요일) `algo-weekly`를 권한다.

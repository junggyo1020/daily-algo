# 대시보드

## 갱신만 필요한 경우 (대부분)

```bash
cd ~/willy/GitHub/daily-algo
python3 scripts/algo.py export
python3 scripts/algo.py stats
```

`stats` 출력이 터미널용 요약이다. 숫자만 확인하려는 질문이면 여기서 끝낸다 —
대시보드를 매번 재발행할 필요는 없다.

웹 대시보드를 실제로 갱신해야 하면 `algo-dashboard-builder` 에이전트를 `model: "opus"`로
호출한다. 전달: `dashboard/data.json`, `dashboard/artifact_url.txt`(있으면 그 URL을 갱신).

## 직접 만들거나 고칠 때

`artifact-design`과 `dataviz` 스킬을 먼저 읽는다. 그 다음 아래 규약을 지킨다.

**데이터는 인라인.** 발행된 페이지는 로컬 파일을 못 읽는다. `data.json`을 `<script>` 상수로
그대로 박는다. 갱신 = 재발행이다.

**URL은 하나.** `dashboard/artifact_url.txt`에 저장된 URL을 `Artifact`의 `url`로 지정해
갱신한다. 새 URL을 만들면 북마크가 죽은 데이터를 가리킨다. 발행 후 URL을 그 파일에 저장한다.

**화면 순서는 행동 순서.** 위에서부터: 오늘 할 일 → 이번 주 진행 → 역량 레이더 →
마지막 시도 경과 → 오답 원인 → 시간 추이 → 복습 큐 → 최근 기록.
사용자가 10초 안에 "지금 뭐 하면 되지"를 알아야 하므로 "오늘 할 일"이 가장 크다.

**0점과 표본 0을 구분한다.** `samples: 0`은 **아직 측정하지 않았다**는 뜻이다.
막대에서 다른 패턴과 색으로 그리고 범례에 명시한다. 둘을 섞으면 측정하지 않은 유형과 0점인 유형이 같은 모양이 된다.

**감쇠는 두 값을 같이 보여준다.** `base`(감쇠 전 점수)와 `mastery`(현재). 둘의 간격이
"안 해서 떨어진 양"이다. 현재 점수만 보여주면 사용자가 실력이 없다고 오해한다.

**빈 상태를 설계한다.** 기록 5건 미만이면 역량 차트와 추이 차트를 비활성으로 두고
"진단 n/12 진행 중"과 오늘 할 일만 크게 보여준다. 0으로 채워진 차트는 낙담만 준다.

## 지표 정의 (해설할 때 쓸 근거)

- `mastery = base × 0.5^(경과일/60)` — 반감기 60일. 30일 방치 ≈ 71%.
- `base` = 최근 가중 정답률. 결과별 점수 1.0 / 0.7 / 0.4 / 0.1 (제한시간내정답 / 시간초과정답 /
  힌트정답 / 실패), 최근 시도에 `0.8^k` 가중.
- 상태 구간: 80 이상, 60-79, 35-59, 35 미만, 표본 0.
- 단계는 날짜가 아니라 상태로 결정된다: 미터치 유형 존재 → `진단`, 60미만 존재 → `보강`, 전부 60+ → `실전`.
- 주 지표는 **주간 스트릭**이다(주 5일 달성 연속 주). 교대 근무나 야근으로 일 단위가 끊겨도 유지된다.

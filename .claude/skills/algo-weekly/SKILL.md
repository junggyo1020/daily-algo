# 주간 진단 사이클

실행 모드: **서브 에이전트 파이프라인**(이 환경에는 `TeamCreate`/`TaskCreate`가 없다).
3개 에이전트를 순차로 호출하고, 데이터는 `_workspace/` 파일로 넘긴다.
소요 목표 **20분**. 매일 45분을 지키게 하려면 주간 사이클이 무거워서는 안 된다.

```
export → [algo-diagnostician] → 01_diagnosis.md
                                      ↓
         [algo-curriculum-designer] ─→ 02_curriculum.md   (내부에서 algo-problem-scout 호출)
                                      ↓
         [algo-dashboard-builder]  ─→ 대시보드 URL 갱신
```

모든 `Agent` 호출에 **`model: "opus"`**를 명시한다. 진단 품질이 이 루틴 전체의 가치를 결정한다.

## Phase 0 — 데이터 갱신과 진행 가능 판단 (1분)

```bash
cd ~/willy/GitHub/daily-algo
python3 scripts/algo.py export
python3 scripts/algo.py stats
```

기록이 **5건 미만이면 전체 사이클을 돌리지 않는다.** 기록 2~3건으로 그린 진단은 다음 주 계획을
엉뚱하게 쏠리게 만든다. 이 경우 `stats` 출력과 "진단 n/12 진행 중, 12유형을 한 번씩 푼 뒤 첫 진단"만
보고하고 종료한다.

1주 이상 공백 후라면 그 사실을 먼저 알린다 — 감쇠 때문에 점수가 전반적으로 내려가 있고,
감쇠 공식에 따른 정상 동작이다.

## Phase 1 — 진단

`algo-diagnostician`을 호출한다. 전달할 것: 분석 기간(주간이면 최근 7일 + 누적, 월간이면 전체),
`dashboard/data.json` 경로, 월간 여부.

산출물 `_workspace/01_diagnosis.md`를 받으면 **"다음 주 우선순위 3개"가 숫자 근거를 달고 있는지**
확인한다. 근거 없는 우선순위는 반려하고 1회 재호출한다.

## Phase 2 — 커리큘럼

`algo-curriculum-designer`를 호출한다. 전달할 것: `01_diagnosis.md` 경로, 다음 주 날짜 범위,
현재 단계(`data.json`의 `phase`).

산출물 `_workspace/02_curriculum.md` 수용 기준:
- 날짜별 표가 7일 전부 채워져 있다(예비일과 휴식도 명시적으로 적혀 있어야 한다)
- 신규 3 / 복습 2 배분이 지켜졌다
- 새 개념이 2개를 넘지 않는다
- 문제 링크가 `verified: true`인 것만 들어갔다 (못 구한 칸은 "당일 탐색"으로 표기)

## Phase 3 — 대시보드

`algo-dashboard-builder`를 호출한다. 전달할 것: `dashboard/data.json`,
`_workspace/02_curriculum.md`, `dashboard/artifact_url.txt`(있으면).

**기존 URL이 있으면 반드시 그 URL을 갱신**하도록 지시한다. 새 URL이 생기면 사용자가 북마크한
대시보드가 죽은 데이터로 남는다.

## Phase 4 — 종합 보고 (사용자에게)

긴 보고서를 다시 쓰지 않는다. 다음 5줄만 출력한다.

```
단계: 보강 (지난주 진단 → 보강 전환)
이번 주: 5/5 달성, 주단위 연속 3주
가장 큰 변화: 그래프 탐색 45 → 72 (복습 2회)
다음 주 초점: 동적 계획법 점화식(신규), 이진 탐색 감쇠 회복(복습)
대시보드: <URL>   다음 주 계획: _workspace/02_curriculum.md
```

그리고 커밋한다:
```bash
git add -A && git commit -q -m "$(date +%Y-%m-%d) 주간 진단 및 다음 주 계획"
```

## 월간 모드 (매월 첫 토요일)

주간과 같은 파이프라인에 두 가지를 더한다.
1. 진단 범위를 전체 로그로 확대하고, **12주 사이클 단계 전환**을 명시적으로 판정한다.
2. `data/types.json`의 유형별 `target_minutes`가 현실적인지 점검한다 — 특정 유형에서
   항상 목표를 초과하면 목표시간 자체가 잘못 잡혔을 수 있다. 조정 시 사유를 커밋에 남긴다.
3. `python3 scripts/verify.py`를 돌려 하네스 자체를 점검한다. 한 달 동안 스킬과 엔진을
   손봤다면 문서의 약속과 코드의 동작이 갈라졌을 수 있고, 그 불일치는 사용자가
   일어나지 않는 일을 믿게 만든다. 실패 항목이 있으면 커리큘럼보다 먼저 고친다.

## 에러 핸들링

| 상황 | 처리 |
|---|---|
| 에이전트 1회 실패 | 1회만 재호출. 재실패 시 그 단계 산출물 없이 진행하고, 최종 보고에 **누락을 명시**한다 |
| 진단 실패 | `algo.py today` 기반 최소 계획(복습 목록과 아직 안 푼 유형)으로 Phase 2 진행 |
| 커리큘럼 실패 | 대시보드만 갱신하고, 다음 주는 매일 `algo-daily`의 `today` 추천으로 운영한다고 보고 |
| 대시보드 발행 실패 | `dashboard/index.html` 로컬 파일 경로를 안내한다. 데이터는 유실되지 않는다 |
| 상충하는 진단 | 삭제하지 않고 양쪽을 출처와 함께 병기한다. 기록이 적을 때 정상적으로 발생한다 |
| `log.jsonl` 파싱 실패 | 즉시 중단하고 깨진 줄 번호를 보고한다. 임의 복구하지 않는다 |

`_workspace/`의 중간 산출물은 지우지 않는다. 다음 사이클에서 "지난주에 무엇을 미뤘는지"를
확인하는 근거가 된다.

## 테스트 시나리오

**정상 흐름** — 로그 12건(6유형을 풀었고 동적 계획법 2회 실패 포함), 토요일 실행.
기대: 진단이 동적 계획법을 `학습 공백`으로, 이진 탐색을 `감쇠`로 분리 판정 → 커리큘럼이 새 개념 2개 이하로
7일 표 작성(복습 2칸은 DP 실패 문제들) → 대시보드 기존 URL 갱신 → 5줄 보고.

**에러 흐름** — 네트워크 차단 상태에서 실행.
기대: Phase 1과 2는 정상 진행(로컬 데이터만 씀), 스카우트가 문제 확보에 실패해 해당 칸이
"당일 탐색"으로 남고, Phase 3 발행이 실패해 로컬 `index.html` 경로가 안내된다.
사이클 전체가 중단되지 않고, 보고에 "문제 링크 3칸 미확보 / 대시보드 로컬만" 이 명시된다.

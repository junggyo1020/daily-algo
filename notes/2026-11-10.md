# 2026-11-10 주차 요금 계산 (프로그래머스 92341, Lv.2)

유형: 구현과 시뮬레이션 / 목표 25분 / 실제 76분 (1차 35분, 2차 41분)
결과: 힌트 후 정답, 프로그래머스 정확성 100.0

## 어떻게 접근했나

입차 기록을 맵에 넣어두고 출차 때 꺼내서 시간 차이를 누적하는 구조로 잡았다.
마지막에 맵에 남아 있는 차량은 23:59로 마감했다. 이 설계는 1차와 2차 모두 같았고 맞았다.
차량번호 오름차순 출력이 필요해서 누적 시간 맵을 TreeMap으로 두었다. 정렬 코드를 따로 안 써도 됐다.

## 막힌 지점과 이유

1차는 컴파일조차 안 됐다. StringTokenizer를 쓰면서 `throws IOException`을 붙였는데
그건 BufferedReader로 입력을 읽을 때 필요한 것이다. 백준 습관이 따라왔다.
시간 차이 함수도 두 군데 틀렸다. `substring(2)`로 분을 떼려 해서 콜론이 섞였고,
`(h2-h1)*60 - (m2-m1)` 로 분 부호를 뒤집었다.

가장 큰 구멍은 `int diff = calculate(...)` 로 계산해놓고 그 값을 안 쓴 것이다.
바로 아래에서 `+1` 을 더하고 있어서 누적 시간이 아니라 출차 횟수가 쌓였다.
설계가 맞는데 결과가 안 나오니 설계를 의심하면서 시간이 녹았다.

2차에서는 예제1만 통과했다. 요금표 숫자 180, 5000, 10, 600을 코드에 박아 넣어서,
요금표가 다른 예제2와 예제3이 틀렸다. 문제가 인자로 준 값을 인자에서 꺼내 쓰지 않았다.

남은 차량 루프에서 순회 중에 `parkingSpace.remove()` 를 호출한 것도 있었다.
세 예제 모두 미출차 차량이 한 대뿐이라 안 터졌을 뿐, 두 대 이상이면
ConcurrentModificationException 이 난다. 직접 만든 반례(미출차 2대)로 확인했다.

반례를 만들 때 `"3:00"` 처럼 네 글자 시각을 넣어서 한 번 더 터졌다.
제한사항에 시각은 길이 5라고 적혀 있으므로 들어올 수 없는 입력이었다.
코드 버그가 아니라 반례가 틀린 경우였다.

## 배운 Java API와 패턴

TreeMap 은 키 정렬이 공짜다. 결과를 키 순서로 내야 하는 문제면 바로 꺼낸다.
정수 올림은 분기 없이 `(a + b - 1) / b` 한 줄이다.
컬렉션 순회 중 제거는 `Iterator.remove()` 로만 한다. 맵을 직접 건드리면 예외가 난다.
프로그래머스 제출은 클래스 이름이 `Solution` 이어야 하고 solution 은 인스턴스 메서드다.

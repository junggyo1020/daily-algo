# 2026-11-12 문자열 압축 (프로그래머스 60057, Lv.2)

유형: 문자열 / 목표 25분 / 실제 41분
결과: 미해결 (25분 벽 초과로 중단)

## 어떻게 접근했나

자르는 단위 k를 1부터 끝까지 돌리면서, 각 k마다 압축 결과 길이를 만들어
최솟값을 갱신하는 구조로 잡았다. 전체 접근은 맞다.
toCharArray 로 한 번 꺼내두고 인덱스로 조각을 만든 것도 괜찮았다.

## 막힌 지점과 이유

다섯 예제의 출력이 전부 입력 길이와 같았다. 압축이 한 번도 일어나지 않았다는 뜻이다.
예제5만 통과한 것은 정답이 우연히 원본 길이 17이었기 때문이다.

여기서 배운 것은 디버깅 순서다. 틀린 값 하나를 들여다보는 대신
틀린 값들의 공통 패턴을 먼저 봤어야 했다. "전부 입력 길이와 같다"를 알아차렸다면
의심 범위가 코드 전체에서 조각 비교 한 줄로 좁혀졌다.

## 다음에 같은 실수를 막을 체크 한 줄

여러 테스트가 동시에 틀리면 값 하나를 파기 전에 틀린 값들의 공통점을 먼저 본다.

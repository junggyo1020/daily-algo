# daily-algo

퇴근하고 집에 와서 Java로 하루 한 문제씩 푼다. 한 번에 45분.

실력을 유지하려고 푼다. 코딩테스트는 손을 놓으면 금방 감이 떨어지는데, 어느 유형이 얼마나 떨어졌는지는 체감으로 알기 어렵다. 그걸 점수로 보이게 만든 저장소다.

## 시작하기

Java 21과 Python 3, 그리고 [Claude Code](https://claude.com/claude-code)가 필요하다.

```bash
git clone https://github.com/junggyo1020/daily-algo.git
cd daily-algo
claude
```

세션이 열리면 `오늘 문제`라고 입력한다. 그 뒤는 `.claude/` 안의 설정이 개념 설명부터 기록까지 끌고 간다.

## 하루 45분

| 시간 | 하는 일 |
|---|---|
| 30초 | `algo.py today` 가 복습과 신규 중 하나를 고른다 |
| 8분 | 그날 유형의 개념 설명. 신규일 때만 하고 문제 힌트는 넣지 않는다 |
| 25분 | 풀이 |
| 7분 | 피드백. 복잡도, Java API, 반례 |
| 5분 | 기록, 커밋, push |

25분을 넘기면 멈춘다. 답도 풀이도 보지 않고 그대로 덮는다. 못 푼 문제는 다음 날 1순위로 다시 나오니 손해는 없다. 한 문제에 한 시간을 쓰면 다음 날 루틴이 무너진다.

야근한 날은 25분짜리 축소모드로 돌린다. 복습 한 문제와 기록만 남기면 된다.

## 토요일 20분

`주간 진단`이라고 입력하면 지난 한 주 기록을 분석해 약점을 짚고 다음 주 7일 계획을 짠다. 대시보드도 새로 만든다.

## 세 가지 장치

평범한 "하루 한 문제"와는 여기서 갈린다.

### 틀린 문제는 반드시 다시 나온다

| 결과 | 다음 복습 |
|---|---|
| 미해결 | 1일 뒤 |
| 힌트 후 정답 | 3일 뒤 |
| 시간초과 정답 | 7일 뒤 |
| 시간내 정답 1회 | 21일 뒤 |
| 시간내 정답 2회 연속 | 60일 뒤 |
| 시간내 정답 3회 연속 | 목록에서 제거 |

새로 푼 문제만 쌓으면 한 달 뒤 같은 유형에서 또 막힌다. 그래서 주 5일 중 2일은 복습으로 고정했다.

### 안 풀면 점수가 내려간다

```
현재 점수 = 감쇠 전 점수 × 0.5^(마지막으로 푼 뒤 지난 날 / 60)
```

60일마다 절반이 된다. 마지막으로 푼 날에서 30일이 지나면 71%가 남는다. 한 번 맞혔다는 기록만으로 점수를 유지해주면 "작년에 풀어봤다"와 "지금도 풀린다"가 같은 값이 된다.

점수가 낮을 때 원인은 두 갈래로 갈린다.

| 모양 | 뜻 | 처방 |
|---|---|---|
| 감쇠 전 점수가 높고 마지막으로 푼 날이 오래됨 | 안 푼 기간만큼 내려갔다 | 복습 한 문제 |
| 감쇠 전 점수 자체가 낮음 | 학습 공백 | 개념부터 |

대시보드가 이 둘을 다른 색으로 보여준다.

### 틀린 이유를 여덟 가지로 나눈다

| 원인 | 뜻 |
|---|---|
| 유형미인지 | 어떤 알고리즘을 써야 할지 떠올리지 못함 |
| 복잡도오판 | 시간이나 공간 복잡도를 잘못 계산해 시간초과 |
| 경계조건 | 빈 입력, 원소 1개, 최댓값, 동일값 같은 끝값 |
| 자료구조선택 | 답은 맞지만 비효율적이거나 부적절한 자료구조 |
| 구현실수 | 인덱스, off-by-one, 조건문 뒤집힘 같은 코딩 실수 |
| 문제오독 | 요구사항을 잘못 읽음 |
| API미숙 | Java 표준 API 사용법이 막힘 |
| 수학오버플로 | int 오버플로, 모듈러, 조합과 확률 공식 |

유형과 원인을 교차하면 "동적 계획법 점수가 낮다"가 "동적 계획법은 점화식 수립에서 막힌다"로 바뀐다. 시간 안에 맞힌 문제라도 과정에서 틀린 부분이 있으면 분류한다.

## 12주 사이클

단계는 쌓인 기록으로 바뀐다. 교대 근무나 야근으로 며칠 밀려도 날짜만으로는 넘어가지 않는다.

| 단계 | 조건 | 하는 일 |
|---|---|---|
| 진단 | 아직 안 푼 유형이 남음 | 12유형을 Lv.1~2로 한 번씩 푼다. 현재 상태를 재는 기간 |
| 보강 | 전 유형을 한 번씩 풀었고 점수 60 미만이 남음 | 약점 유형 집중, 유형 공개, 한 주에 새 개념 2개까지 |
| 실전 | 전 유형 60 이상 | Lv.2~3 블라인드(유형 비공개), 주말 타임어택 |

실전까지 갔다가 보강으로 내려오는 일이 생긴다. 안 푼 날이 쌓이면 점수가 떨어지니 당연하다. 그 왕복이 유지하는 상태다.

## 대시보드

`dashboard/index.html`이 매일 다시 만들어진다. 12유형 점수와 감쇠량, 14일 넘게 안 푼 유형, 틀린 이유 분포, 복습 목록, 16주 히트맵이 한 장에 들어간다. 오늘 뭘 풀어야 하는지가 맨 위에 가장 크게 나온다.

## 문제는 어디서 가져오나

프로그래머스가 1순위다. 백준은 2026년 4월 28일부터 멈춰 있다. 데이원컴퍼니가 인수했고 재오픈은 연기됐다(2026년 11월 9일 확인). 문제 수와 난이도 분포가 넓으니 다시 열리면 1순위도 바뀐다. 스카우트 담당이 매번 접속 상태를 확인한다.

한 가지 주의할 점. 프로그래머스는 난이도를 JavaScript로 그려서 레벨을 자동으로 읽어올 수 없다. 기록할 때 **페이지에 표시된 실제 Lv.** 를 직접 쓴다. 레벨이 틀어지면 목표시간이 틀어지고 점수까지 왜곡된다.

## 명령어

```bash
python3 scripts/algo.py today     # 오늘 뭘 풀어야 하는지
python3 scripts/algo.py stats      # 터미널 요약 (점수 표, 틀린 이유 분포)
python3 scripts/algo.py export     # dashboard/data.json 생성
python3 scripts/algo.py log --help # 기록 옵션
python3 scripts/verify.py          # 문서와 코드가 어긋났는지 검사
```

이 저장소에서 제일 위험한 고장은 **문서와 코드가 어긋나는 것**이다. 문서에는 "60일 뒤에 복습한다"고 적혀 있는데 코드가 거기까지 가지 못하면 일어나지 않는 일을 믿고 공부하게 된다. `verify.py`는 그런 어긋남과 `CLAUDE.md`에 적어둔 표현 규칙 위반을 같이 검사한다.

## 구조

```
data/log.jsonl        모든 지표의 출처. 점수와 복습 일정이 여기서 나온다
data/types.json       12유형, 유형별 목표시간, 틀린 이유 8종
scripts/algo.py       학습 엔진 (추천, 점수, 복습 목록, 연속 기록, export)
scripts/verify.py     문서와 코드의 어긋남 검사
src/main/java/daily/  날짜별 풀이. java 파일 단독 실행 (java <경로>)
notes/YYYY-MM-DD.md   당일 개념, 막힌 지점, 배운 API
dashboard/            data.json 과 만들어진 대시보드
.claude/agents/       진단, 커리큘럼, 스카우트, 대시보드 담당 4개
.claude/skills/       algo-daily, algo-concept, algo-feedback, algo-weekly, algo-dashboard
CLAUDE.md             이 저장소에서 지킬 표현 규칙
```
